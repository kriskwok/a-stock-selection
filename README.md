# A股智能选股工具

版本：1.1.1

> 项目地址：https://github.com/kriskwok/a-stock-selection
>
> 本项目仅用于投研辅助，不构成任何买卖建议。
>
> 作者：kriskowk

## 核心定位

运行本 skill，从公开、零 API Key 数据源生成可追溯的 A 股研究报告。严格区分技术结构、市场题材、成长估值与事件风险，不以市值、成交额或估值字段冒充价格趋势。

按以下五层顺序执行：

1. 扫描近期资讯、强势股、热榜、行业广度和涨跌停情绪；
2. 扩展热点对应的公开行业或概念成分股；
3. 应用市值、流动性和真实趋势门槛，生成技术候选 TOP 10；
4. 补充一致预期、成长估值、公告、解禁、资金流、融资融券和龙虎榜数据；
5. 计算综合研究分，输出综合 TOP 5、风险标签和数据可信度。

## 筛选口径

- 保留涨停或高动量候选，避免机械排除强势突破标的；
- 要求总市值不低于 100 亿元，优先选择 400 亿元以上公司；
- 要求最近交易日成交额不低于 5 亿元，优先选择近 5 日量能放大者；
- 优先使用真实 20/60 日趋势、均线结构和 52 周位置；
- PE/PB 或一致预期缺失时降低数据可信度，不编造或错误替代字段；PB 全量缺失时不得宣称估值完整；
- 技术核心字段不完整时，只输出“候选观察池”，不得发布正式 TOP 5。

## 双分制

保留原始 `技术结构分`，另行计算：

```text
综合研究分
= 65% 技术结构分
+ 15% 市场与题材分
+ 20% 成长估值分
- 风险扣分（最高20分）
```

市场与题材分不得替代真实涨跌幅、均线和量价指标。风险数据缺失时标记“未验证”并降低可信度，不把缺失本身当作负面事件；综合分只使用已验证的正向维度并按可用权重重标定，必须标注“暂定综合研究分”。

## 数据源规则

- 使用腾讯财经获取实时价格、估值、市值和成交额；
- 技术趋势优先使用同花顺独立日线（`d.10jqka.com.cn`）；百度日线返回空记录时视为失败，东方财富前复权日线与 mootdx 不复权日线分别作为后备，其中不复权数据不得跨除权日计算收益；
- 对东方财富请求执行串行限流、随机抖动、会话复用和退避重试；403 立即熔断，连续 `RemoteDisconnected` 在一次重试后按共享 IP 级故障熔断，后续字段必须走独立备源或标为“未验证”；
- 使用同花顺与东方财富交叉验证强势股、热榜和题材归因；
- 使用巨潮、交易所或其他独立来源复核公告及关键风险数据；
- 为每项结果保留来源、数据日期、是否降级、错误原因和字段覆盖率。

## 脚本路由

- `scripts/a_stock_selection.py`：运行完整工作流并生成报告；
- `scripts/data_sources.py`：统一网络请求、限流、共享熔断、数据源追踪与主备降级；
- `scripts/market_context.py`：计算市场温度、行业广度和题材共振；
- `scripts/risk_review.py`：执行公告、解禁、资金、融资融券和龙虎榜风险复核；
- `scripts/valuation.py`：计算一致预期、前向 PE、PEG 和成长估值得分；
- `scripts/data_quality.py`：计算字段覆盖率和数据可信度。

## 快速运行

安装依赖：

```bash
python3 -m pip install -r /path/to/a-stock-selection/scripts/requirements.txt
```

运行完整报告：

```bash
python3 /path/to/a-stock-selection/scripts/a_stock_selection.py
```

`--skip-image` 仅为兼容旧命令保留，当前不会生成 PNG。

使用自定义输出目录：

```bash
python3 /path/to/a-stock-selection/scripts/a_stock_selection.py --output-dir /path/to/output
```

执行小规模烟雾测试或限制批量请求：

```bash
python3 /path/to/a-stock-selection/scripts/a_stock_selection.py --skip-image --max-candidates 2 --enrichment-limit 2
```



## 正式排名门槛

至少取得足够覆盖率的真实区间涨跌幅、收盘价、20 日均线和 60 日均线，才允许生成正式技术候选和综合 TOP 5。若只得到成交额、市值、PE/PB 或单一趋势字段，展示已有数据并明确降级原因。

对技术候选最多取 10 只，再补充：

- 市场温度、题材热榜交集与板块扩散度；
- 机构一致预期 EPS、预测机构数、前向 PE、PEG、营收和净利润增速；
- 未来 90 日解禁、最近 30 日重要公告、近 20 日资金流、融资余额变化和龙虎榜机构买卖。

使用候选池横向分位评价成长估值，不使用所有行业统一的固定 PE 锚点。预测机构少于 3 家时标记“低覆盖”。

当东方财富的 `push2` 或 `datacenter-web` 出现连接重置，不能让其阻断技术排名：同一运行中的后续东方财富字段应快速降级，报告保留失败原因；只要独立日线满足趋势完整性门槛，仍可发布正式技术候选与综合 TOP 5。

## 输出要求

将原始 JSON 写入 `data/`，将 Markdown 和响应式 HTML 写入 `reports/`，不再生成 PNG。报告至少包含：

- 市场温度与涨跌停情绪；
- 题材多源共振；
- 技术候选 TOP 10；
- 综合研究 TOP 5；
- 成长估值与机构覆盖；
- 公告、解禁、资金和龙虎榜风险体检；
- 数据来源、日期、降级记录和覆盖率矩阵。

结论必须同时展示 `技术结构分`、`综合研究分`、`风险扣分` 和 `数据可信度`。使用“趋势延续”“回调观察”“接近前高”“短期涨幅偏快”等审慎措辞，避免“买入”“卖出”“稳赚”“必涨”或目标价。

## 维护要求

- 不把 ETF 期权、逐笔成交、五档盘口、完整 F10 或批量研报 PDF 加入主流程；
- 除非用户明确要求示例产物，否则不提交 `data/`、`reports/` 或缓存；
- 隐藏覆盖严重不足的维度，不展示误导性的局部数据；市场、风险和趋势数据失败时显示“未验证”，不得显示为零值；
- 确保报告结论与实际评分及降级状态一致；
